# TCP服务器协议解析更新规格

## 概述

根据 `通讯处理.txt` 文件中的实际协议格式，更新 TCP 服务器的协议解析器，从二进制协议改为文本协议。

## 当前问题

现有 `ProtocolParser.js` 实现的是二进制协议（基于 0x7E/0x7F 起止符），但实际 DTU 设备使用的是文本协议。

## 实际协议格式

### 1. 注册包
- **发送格式**: `ZC+设备IMEI号`
- **返回格式**: `ZC+OK`
- **示例**: 设备发送 `ZC+123456789012345`，服务器返回 `ZC+OK`

### 2. 心跳包
- **发送格式**: `HB+当前时间戳10位数`
- **返回格式**: `HB+OK`
- **示例**: 设备发送 `HB+1714022400`，服务器返回 `HB+OK`

### 3. 业务数据包
- **发送格式**: `SJ+设备IMEI号,深度,正测值,反测值,测量时间戳`
- **返回格式**: `SJ+OK`
- **示例**: 设备发送 `SJ+123456789012345,10.5,12345,54321,1714022400`，服务器返回 `SJ+OK`

## 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| IMEI号 | 字符串 | 设备唯一标识，15位数字 |
| 深度 | 浮点数 | 测量深度，单位米 |
| 正测值 | 整数 | AD转换原始值 |
| 反测值 | 整数 | AD转换原始值 |
| 时间戳 | 整数 | 10位Unix时间戳 |

## 服务器处理逻辑

### 连接建立与注册验证
1. 等待接收第一个数据包作为注册包
2. 解析提取设备IMEI
3. 在数据库中查询设备是否合法
4. 返回注册成功确认消息

### 心跳保活处理
1. 识别心跳包格式
2. 更新设备最后在线时间
3. 返回心跳响应

### 业务数据处理
1. 解析数据字段（深度、正测值、反测值、时间戳）
2. 存入原始数据表
3. 关联设备ID和测孔编号
4. 返回数据接收确认

## 技术实现要点

1. **文本协议解析**: 使用字符串分割和正则表达式解析
2. **消息边界**: 使用换行符 `\n` 或直接按完整消息处理
3. **数据验证**: 验证IMEI格式、数值范围等
4. **错误处理**: 返回对应的错误响应格式

## 文件修改范围

1. `tcp-server/lib/ProtocolParser.js` - 完全重写协议解析逻辑
2. `tcp-server/lib/MessageHandler.js` - 适配新的消息格式
3. `tcp-server/index.js` - 更新响应发送逻辑
