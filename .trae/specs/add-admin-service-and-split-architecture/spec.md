# 管理端与双数据库架构重构 Spec

## Why
当前系统将面向客户端的业务能力、设备通讯能力和用户前端耦合在同一套架构中，难以支撑任务编排、双端隔离和多客户鉴权。需要在保持通讯服务职责稳定的前提下，新增管理端并重构客户端边界，形成大后端和大前端分层架构。

## What Changes
- 新增管理端服务，负责客户端 HTTP 接入、客户鉴权、任务下发、任务状态轮询和回调客户端结果
- 保持通讯服务职责不变，继续负责设备通讯、原始数据获取和原始数据入库
- 将现有面向用户的客户端重构为独立的大前端/客户端服务，只连接客户端数据库
- 引入双数据库架构：
- 管理端与通讯服务共享管理库
- 客户端独立使用业务库
- 新增任务表与客户表，支持客户端请求鉴权与设备任务编排
- 明确原始数据、成果数据、变形曲线等数据在客户端侧的职责边界
- **BREAKING** 原有单体式“后台 + 前端 + 通讯协作”模式调整为“管理端 + 通讯服务 + 客户端”三层架构

## Impact
- Affected specs: TCP 通讯、指令下发、客户端原始数据查询、成果数据处理
- Affected code: `backend/`、`frontend/`、`tcp-server/`、数据库初始化脚本、系统部署配置

## ADDED Requirements
### Requirement: 管理端服务
系统 SHALL 提供独立的管理端服务，作为客户端访问设备能力的唯一 HTTP 接入层。

#### Scenario: 客户端调用管理端接口
- **WHEN** 客户端通过 HTTP 请求管理端能力接口
- **THEN** 管理端接收请求并进入鉴权、任务创建和结果轮询流程

### Requirement: 客户鉴权
系统 SHALL 提供客户表，并为每个客户分配独立密钥，管理端必须对客户端的每次请求执行鉴权。

#### Scenario: 合法客户请求
- **WHEN** 客户端携带合法客户标识和密钥发起请求
- **THEN** 管理端验证通过并继续处理业务

#### Scenario: 非法客户请求
- **WHEN** 客户端未携带密钥、密钥错误或客户状态无效
- **THEN** 管理端拒绝请求并返回鉴权失败结果

### Requirement: 任务表驱动的设备交互
系统 SHALL 通过管理库中的任务表协调管理端与通讯服务之间的设备任务执行。

#### Scenario: 管理端下发设备任务
- **WHEN** 客户端请求设备操作
- **THEN** 管理端将任务写入任务表并轮询任务状态

#### Scenario: 通讯服务执行设备任务
- **WHEN** 通讯服务轮询到待执行任务
- **THEN** 通讯服务与设备交互、采集原始数据、写入原始数据表并将任务状态更新为已完成或失败

#### Scenario: 管理端返回任务结果
- **WHEN** 管理端轮询发现任务状态为已完成
- **THEN** 管理端调用客户端接口，将该任务对应的原始数据内容返回给客户端

### Requirement: 双数据库隔离
系统 SHALL 将管理端/通讯服务与客户端的数据存储拆分为两个独立数据库。

#### Scenario: 管理库职责
- **WHEN** 管理端或通讯服务运行
- **THEN** 只访问管理库中的客户、任务、设备关系和原始数据等管理侧表

#### Scenario: 客户端业务库职责
- **WHEN** 客户端进行原始数据查询、成果计算或曲线展示
- **THEN** 只访问客户端业务库中的原始数据镜像、成果数据、变形曲线等业务侧表

### Requirement: 客户端业务重构
系统 SHALL 将现有用户端重构为独立客户端，负责面向用户提供原始数据查询、成果数据计算和曲线展示能力。

#### Scenario: 原始数据查询
- **WHEN** 用户在客户端查询原始数据
- **THEN** 客户端从业务库读取对应原始数据记录并提供筛选展示能力

#### Scenario: 成果数据生成
- **WHEN** 用户发起原始数据解析
- **THEN** 客户端根据业务规则生成成果数据和变形曲线，并写入业务库对应表

## MODIFIED Requirements
### Requirement: 通讯服务职责边界
通讯服务 SHALL 保持设备通讯与原始数据入库职责，不直接承担客户端鉴权、客户端结果回调和用户业务展示能力。

#### Scenario: 通讯服务收到待执行任务
- **WHEN** 通讯服务从任务表读取到可执行任务
- **THEN** 它只负责设备交互、任务状态更新和原始数据入库，不直接响应客户端请求

### Requirement: 指令下发链路
原有指令下发能力 SHALL 调整为经由管理端任务表编排执行，而不是由前端直接驱动通讯服务即时调用。

#### Scenario: 客户端发起指令
- **WHEN** 客户端请求设备执行某项操作
- **THEN** 管理端创建任务记录，由通讯服务异步执行，并由管理端向客户端回传结果

## REMOVED Requirements
### Requirement: 单体式统一访问链路
**Reason**: 单一后台同时承担客户端接入、设备通讯编排和业务展示，不利于职责隔离、双数据库管理和客户级鉴权。
**Migration**: 将客户端访问入口迁移至管理端接口，将业务查询与成果计算迁移至客户端服务，将通讯执行保留在通讯服务。
